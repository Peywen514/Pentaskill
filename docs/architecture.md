# 系統架構與資料流程

## 第 1 階段已實作

無第三方 JavaScript 套件的 HTML／CSS／ES Modules 前端。

- `src/catalog.js`：示範課程、四階段、測驗題與暖身任務。
- `src/domain.js`：程度推薦、XP 去重、方案定價、未付款草稿、課程與預約輸入驗證。
- `src/app.js`：畫面與互動，Hash 路由；輸入插入 HTML 前跳脫，文字反饋使用 textContent。
- `src/styles.css`：淺色響應式介面，鍵盤焦點與減少動態效果支援。
- `scripts/serve.mjs`：只提供公開前端路徑的本機 HTTP 伺服器。
- `tests/`：領域規則與公開檔案範圍的自動測試。

體驗資料使用 `pentaskill-preview-v1` localStorage Key。這不是身分或授權依據；任何本機資料都視為可修改。正式會員、金鑰、交易與個資不得放入此機制。

## 正式版架構提案（尚未實作）

前端 → 後端 API → 關聯式資料庫；後端分別串接金流、影片／檔案儲存及 Zoom。實際技術選型於第 2 階段確認。

### 資料邊界

| 資料 | 核心規則 |
| --- | --- |
| users、sessions、roles | 伺服器驗證身分；安全 Cookie；後端檢查角色及資源擁有者 |
| courses、lessons、materials | 目錄可公開，付費內容在後端驗證授權後發短效連結 |
| products、plans | 商品有穩定 ID；錄播與個教權益分開；價格保留版本 |
| quotes、quote_items | 綁定受益學員、課程、方案、價格、效期；接受報價不代表已付款 |
| orders、order_items、payments | 伺服器計價並保存商品快照；金流交易 ID 唯一 |
| enrollments | 明確對應使用者與課程，不以某課程 ID 當全站通行權 |
| coaching_credit_ledger | 記錄核發、保留、消耗與歸還；同一事件不得重複記帳 |
| mentor_slots、bookings | 交易內驗證堂數並鎖定時段；同一有效時段只能有一筆預約 |
| meeting_links | 私人存取；Zoom 等候室與密碼；不公開主持人連結 |
| assessments、quest_awards、progress | 存放題庫版本、推薦理由、唯一獎勵及實際影片進度；XP 不可支付 |

### 付款

學員選方案 → 後端確認現行價格／有效報價 → 建立待付款訂單 → 金流結帳 → 後端驗證回呼簽章、商店、交易、金額及狀態 → 以冪等操作更新付款、課程授權與個教額度。瀏覽器返回成功頁不代表已付款。退款另記紀錄並依政策調整權益。

### 個教預約

查詢業師可用時段 → 後端確認個教額度 → 交易內保留堂數與時段 → 建立／確認外部會議 → 私人預約頁顯示連結。若會議建立失敗，標示待處理並安全重試，不顯示假連結。取消與改期也以唯一事件處理，避免重複歸還堂數。

資料庫以 UTC 儲存時間，介面顯示 Asia/Taipei。Zoom 承載會議影音；本站仍會產生一般網頁、資料 API 與錄播服務的流量。

### 學習地圖

第 1 階段採確定性情境評量，從最早出現的基礎缺口推薦起點。全對推薦開發者階段；不宣稱通過專業認證。可以自由探索所有階段。暖身任務與付費課程內容分開，完成任務不能自動開課。
