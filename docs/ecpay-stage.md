# 綠界付款：隔離測試規劃

此程式目前僅支援 `ECPAY_MODE=stage`，不提供正式金流模式。未設定時付款 API 回覆 503，正式收款不可用。正式課程、價格、付款方式、發票、退款、帳務對帳、付款遺漏通知補查、影片授權及個教額度均須另行完成並驗證。

建議在獨立 Worker、獨立 D1、綠界測試特店執行，避免測試紀錄進入正式會員／訂單資料庫。測試環境的 merchant ID / HashKey / HashIV 只設在服務端設定中，正式憑證不得寫入儲存庫、網頁、日誌或對話。`ECPAY_SITE_ORIGIN` 必須是測試 Worker 的 HTTPS origin。正式站不得套用測試金鑰或測試付款配置。

登入會員由伺服器依已上架課程 ID 取價、建立待付款訂單快照，並由綠界通知攜帶的訂單號尋回會員、課程及金額。只有檢查碼、特店編號、訂單號、交易編號、金額與成功狀態均正確，且 SimulatePaid 為 0，才在同一個 D1 batch 標記付款並建立課程授權。重送通知不應重複發放。SimulatePaid=1 僅供檢查通知通道，絕不開通授權。

正式啟用前需完成：綠界沙盒從手機及桌機建單／付款／通知端對端測試；跨裝置授權與登入隔離；延遲通知與對帳、退款／撤銷、重複結帳及客服處理；Cloudflare 權限與資料備份；受保護教材播放驗收。具體金流付款方式及平台功能須依綠界核准與使用者需求確認。
